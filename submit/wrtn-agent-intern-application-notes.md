# 뤼튼 Agent Developer 인턴 지원서 초안

## 1. 본인이 수행한 프로젝트 중 가장 인상 깊거나 주요한 프로젝트
가장 인상 깊었던 프로젝트는 `WorkFlow Agent`입니다.  
사내 규정 검토를 돕는 멀티 Agent 시스템이었는데, 단순히 답변을 생성하는 수준이 아니라 실제 판단 보조에 가까운 역할을 해야 했습니다. 이 과정에서 sLLM이 존재하지 않는 조항을 인용하면서도 높은 confidence를 주는 문제를 반복적으로 마주했고, 이 경험이 제가 Agent를 바라보는 기준을 바꾸는 계기가 됐습니다.

저는 이 프로젝트에서 "모델 성능을 더 올리는 것"보다 "틀렸을 때 위험하게 보이지 않도록 시스템을 설계하는 것"이 더 중요하다고 판단했습니다. 그래서 Judgment Agent 구조, 공통 LLM 모듈, Guardrail, confidence 보정 로직을 중심으로 문제를 풀었습니다. 이 경험을 통해 Agent는 잘 답하는 것만큼 틀릴 때 어떤 식으로 제어되는지가 중요하다는 점을 배웠습니다.

## 2. 프로젝트의 시작 배경과 목표
프로젝트의 시작 배경은 분명했습니다. 규정 검토처럼 신뢰도가 중요한 도메인에서는 그럴듯한 오답이 더 위험한데, 당시 시스템은 그 위험을 충분히 제어하지 못하고 있었습니다. 실제로 잘못된 답변인데도 높은 confidence를 주거나, 존재하지 않는 조항을 인용하는 문제가 있었습니다.

프로젝트의 목표는 단순히 "정확한 답변을 더 많이 만드는 것"이 아니라, 실제로 사용할 수 있는 수준의 Agent를 만드는 것이었습니다. 그래서 정확도뿐 아니라 JSON 유효율, confidence calibration, 환각 여부 같은 지표를 함께 봐야 한다고 정의했습니다. 이 목표 설정이 이후 구현 방향을 결정하는 기준이 됐습니다.

## 3. 프로젝트 내 본인의 역할 및 기여도, 제안하거나 주도한 아이디어
저는 Judgment Agent와 공통 LLM 모듈 구조 설계를 맡았고, GPT/Claude/vLLM을 provider 교체 방식으로 붙일 수 있도록 인터페이스를 정리했습니다. 또한 키워드, 조항 검증, 카테고리 일치, 일관성 확인의 4중 Guardrail 아이디어를 제안하고 구현 방향을 주도했습니다.

confidence 값을 그대로 신뢰하지 않고 5-factor 기준으로 다시 보정하자는 방향도 제가 제안한 부분입니다. LoRA 학습에서도 단순히 데이터를 늘리기보다, 약점 사례를 타겟팅하는 것이 더 중요하다고 판단해 v3 데이터셋을 소수 사례 중심으로 다시 구성했습니다. 이 과정에서 "문제를 세분화해서 다루는 방식"이 실제 품질 개선에 더 효과적이라는 것을 확인했습니다.

## 4. 산출물 및 결과·성과
이 프로젝트를 통해 정확도는 `37% -> 85%`로 개선됐고, JSON 유효율은 `70% -> 97%`로 높아졌습니다. 과도하게 높게 나오던 confidence도 실제 위험도를 반영하도록 낮추는 방향으로 보정했습니다.

산출물 측면에서는 FastAPI 기반 서버, LangGraph 흐름, vLLM+LoRA 서빙 구조, Qdrant 연동, Docker/AWS 배포 구조까지 경험했습니다. 저는 이 결과가 단순히 수치 개선에 그치지 않고, "실무에서 더 안전하게 사용할 수 있는 Agent"에 가까워졌다는 점에서 의미가 크다고 생각합니다.

## 5. 회사를 선택할 때 중요하게 생각하는 기준
제가 회사를 선택할 때 가장 중요하게 보는 기준은 세 가지입니다.

첫째, 기술 실험이 실제 사용자 문제와 연결되는가입니다. 흥미로운 기술을 다루는 것도 중요하지만, 그 기술이 실제 서비스와 문제 해결로 이어지는 환경에서 더 많이 배우고 성장할 수 있다고 생각합니다.

둘째, 빠르게 시도하고 검증할 수 있는가입니다. 저는 감으로 오래 고민하기보다, 가설을 세우고 작게 실험하고 수치로 확인하는 방식이 잘 맞습니다.

셋째, 주니어도 문제 정의와 구조 설계에 깊게 참여할 수 있는가입니다. 단순히 주어진 기능을 구현하는 것보다, 왜 이 문제를 이렇게 풀어야 하는지 함께 고민할 수 있는 환경을 중요하게 생각합니다.

뤼튼은 컨슈머 AI와 AX를 동시에 전개하고 있고, 공식적으로도 Agentic AI와 Productivity Bottleneck 해결을 이야기하고 있어 제가 중요하게 생각하는 기준과 잘 맞는다고 느꼈습니다.

## 6. 중·장기 커리어 목표 및 방향
중기적으로는 신뢰 가능한 Agent 시스템을 설계하는 백엔드/AI 엔지니어가 되고 싶습니다. 단순히 모델을 붙이는 수준이 아니라, 검색 구조, 상태 관리, 검증 체계, 운영 안정성까지 함께 볼 수 있는 사람이 되는 것이 목표입니다.

장기적으로는 사람이 반복적으로 판단하고 정리하던 업무를 대신할 Agent를 만들되, 그 Agent가 잘못 작동했을 때도 위험을 줄일 수 있도록 설계하는 엔지니어가 되고 싶습니다. 저는 앞으로도 "더 똑똑한 모델"보다 "더 신뢰할 수 있는 시스템"을 만드는 방향으로 성장하고 싶습니다.
