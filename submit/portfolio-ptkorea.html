AS-IS

PyMate

데이터 검색 품질 정량 진단 + AWS 프로덕션 배포

"데이터 품질이 낮다"는 피드백의 원인을 4개 지표로 분리 측정하여 진짜 병목을 특정하고, AWS 클라우드에 안정적으로 배포

개요

팀(4명)으로 개발한 Python 학습 도우미 RAG 챗봇. "답변이 부정확하다"는 피드백의 원인을 정량 진단하여 구조적으로 해결하고, AWS 클라우드에 안정적으로 배포.

역할: Qdrant 벡터 DB 설계, 임베딩 차원 최적화(768D→3,072D), Django 프로덕션 배포(AWS EC2 + Nginx + Gunicorn)

데이터 검색 품질 정량 진단

AS-IS

"답변이 부정확하다"는 피드백이 반복되었지만, 문제가 검색 단계인지 생성 단계인지 구분 불가. 감으로 모델을 바꾸거나 프롬프트를 수정 — 병목을 모르고 약을 바꾸는 것과 동일.

TO-BE

RAGAS 4개 지표(Context Precision·Recall·Faithfulness·Answer Relevancy)를 도입하여 검색·생성을 분리 측정. Faithfulness는 높지만 Precision이 낮음 → 병목은 "검색 단계의 임베딩 품질"로 재정의. 임베딩 768D→3,072D 교체 + Qdrant 재설계로 Precision 0.83→0.97(+14.4%).

AWS 클라우드 프로덕션 배포

AS-IS

Flask MVP는 ORM 마이그레이션·정적 파일 서빙·관리자 페이지 등 프로덕션 기능이 부재. AWS EC2 배포 시 Nginx → Gunicorn → Flask 연결에서 소켓 바인딩 문제로 반복적인 502 에러 발생.

TO-BE

Flask → Django 전환으로 ORM migration, admin, collectstatic 프로덕션 인프라 표준화. Nginx → Gunicorn → Django 소켓 바인딩을 직접 구성하여 502 에러 해결. Reranker를 cross-encoder로 경량화하여 레이턴시 -1초.
