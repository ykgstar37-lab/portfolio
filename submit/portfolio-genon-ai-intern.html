RAG 병목 재정의

AS-IS
  • 문제 정의 부재. "답변이 부정확하다"는 피드백만 반복되고, 검색 문제인지 생성 문제인지 분리 측정 불가.
  • 잘못된 대응 방향. 병목 확인 없이 바로 LLM 교체로 가자는 의견, 비용만 늘고 원인을 놓칠 위험.
  • 제품 리스크. 관련 없는 문서가 먼저 노출되어 첫 답변 성공률이 흔들리고, 재질문 증가 가능성.
TO-BE
  • 병목 분리. RAGAS 4개 지표로 검색·생성을 분리 측정해, Faithfulness는 높고 Precision이 낮다는 근거로 embedding 병목 특정.
  • 해결 구조. 768D→3,072D 교체, HyDE, BM25+RRF 조합으로 짧은 질문과 긴 문서 사이의 vocabulary mismatch 해소.
  • 결과 해석. Precision 0.83→0.97 (+14.4%p). 첫 답변 성공률과 재질문 감소의 선행지표로 해석.
Decisions · "왜 이 숫자인가"

판단 근거

  • 왜 임베딩 교체부터 했나: RAGAS 측정에서 Context Precision 0.83이 병목, Answer Relevancy는 양호. LLM 교체가 무의미하다고 판단해 검색 품질을 먼저 건드렸습니다.
  • 왜 768D → 3,072D인가: 1,024D·1,536D도 후보였지만 text-embedding-3-large가 한국어 교육 도메인 용어를 더 잘 잡는 걸 평가셋에서 확인. 단일 교체로 Precision +14.4%p.
  • 왜 Reranker를 경량화했나: bge-reranker-v2-m3는 정확하지만 무거워, ms-marco-MiniLM-L6-v2로 교체해 약 -1초. 정확도 손실은 평가셋에서 무시할 수준임을 미리 확인.

Guardrail 설계

AS-IS
  • 위험한 실패. "인턴에게 AWS 접근 권한을 줘도 되나요?" 질의에 Base 모델이 오답을 내면서도 confidence 0.92를 반환.
  • 환각 문제. 존재하지 않는 조항 번호를 근거처럼 제시해, 잘못된 응답이 더 신뢰롭게 보임.
  • 기본 성능. 규정 판단 정확도 37.2%로 서비스 레이어에서 바로 쓰기 어려움.
TO-BE
  • 차단 구조. 다단계 Guardrail로 키워드 매칭·조항 존재·카테고리 제한·일관성 모니터링 4종을 분리 적용.
  • Confidence 보정. RAG 품질이 0.2 미만이면 confidence를 max 0.4로 제한해 고신뢰 오답 차단.
  • 결과. 37%→85%. 전수 ML 검증보다 규칙 기반으로 명확한 실패를 먼저 막음.

LoRA 파인튜닝 — 데이터 양 vs 품질 실험

AS-IS
  • 초기 가설. "데이터를 많이 넣으면 좋아진다"는 가정으로 v2에서 98건을 추가 보강.
  • 실험 결과. 성능이 오히려 -3.2%p 하락해 양적 확대가 개선으로 이어지지 않음.
  • 원인. 재량 표현이 섞인 라벨 오염 발견 — 데이터 품질 자체가 병목.
TO-BE
  • 정밀 타겟팅. v3에서 약점 19건만 재설계 (재량 표현 14건 + 경계 케이스 5건).
  • 판단 전환. 양 확대 대신 데이터셋 구성 자체를 바꿔, 틀린 가설을 즉시 수정.
  • 결과. 85.4% 회복 — "더 많이"보다 "어디가 약한가"가 Agent 신뢰성의 출발점.
Decisions · "왜 이 숫자인가"

판단 근거

  • 왜 "4중" Guardrail인가: 오답 패턴을 분류했더니 키워드 누락·조항 환각·카테고리 혼선·앞뒤 모순 4종이 전부. 3중은 모순을 못 잡고 5중부터 직교성이 무너져 4개로 고정.
  • 왜 LoRA v3는 19건만 / RAG는 학습에 안 넣었나: v2에서 98건 보강했더니 -3.2%p 하락 → 라벨 오염 원인, 약점 19건만 재설계. 학습에 RAG 결과를 섞으면 -9.8%p 급락해 "학습은 깨끗한 데이터, 서빙은 RAG 삽입"으로 분리 안정화.

Retrospective · 아쉬운 점 / 다음에 하고 싶은 것

Agent를 신뢰의 대상이 아닌 검증의 대상으로

  • [높음] conditional(재량 표현) 정확도 78% — 목표 85% 대비 -7%p 미달. 경계 모호 케이스("필요한 경우" 등) 학습 데이터 추가 필요.
  • [중간] 멀티턴 미지원 — 단건 Q&A 구조라 세션 맥락이 끊김. 다음 버전에 세션 메모리 추가 예정.
  • [낮음] Reranker가 응답에 +5.7초. 비동기 Reranking·top-k 캐싱으로 개선 여지.
  • 배운 점: Agent 시스템은 "잘 답하는 능력"만큼 "틀릴 때의 거동"이 중요. sLLM 신뢰성을 데이터·코드·인프라 세 층에서 다루는 감각을 익혔습니다.
